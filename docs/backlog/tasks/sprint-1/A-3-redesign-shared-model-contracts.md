# Task A-3: Redesign `shared-model` contracts for the Order/Inventory domain

**Depends on:** A-1 must be merged first (this task references `order-service`/`inventory-service` package names).

## Context
`shared-model` is a Maven library holding only cross-service wire contracts (DTOs + Kafka events) — no JPA entities. It currently still holds an `Article` JPA entity and `ArticlePublishedEvent`, both being retired as part of the pivot away from the article-mirror demo into a real Order → Inventory choreographed saga. See `docs/adr/0001-event-driven-showcase-architecture.md` §4 for why this boundary matters (background only, not required reading).

## Current state (`shared-model/src/main/java/com/example/sharedmodel/`)
- `Article.java` — `@Entity` (Long id, title, author, content, publishedAt, createdAt). **Delete.**
- `ArticlePublishedEvent.java` — `record(String id, String title, String author, Instant publishedAt)`. **Delete**, replaced by the two events below.
- `LoginRequest.java`, `LoginResponse.java`, `RegisterRequest.java` — **leave untouched**, these are unrelated to the article/order domain.
- `shared-model/pom.xml` depends on `jakarta.persistence-api` (needed only because of `Article.java`) and `spring-boot-starter-json`.

## Task

1. Delete `Article.java` and `ArticlePublishedEvent.java`.
2. Add `OrderPlacedEvent.java` as a Java record:
   ```java
   public record OrderPlacedEvent(
           String orderId,
           String customerEmail,
           List<OrderItem> items,
           BigDecimal totalAmount,
           Instant placedAt
   ) {}
   ```
   Add a nested/sibling record `OrderItem(String sku, int quantity)` in the same package (e.g. `OrderItem.java`).
3. Add `InventoryReservationEvent.java` as a Java record:
   ```java
   public record InventoryReservationEvent(
           String orderId,
           ReservationStatus status,
           String reason,
           Instant processedAt
   ) {
       public enum ReservationStatus { RESERVED, REJECTED }
   }
   ```
   `reason` is `null` when `status == RESERVED`; populated with a human-readable explanation when `REJECTED`.
4. `orderId` is a `String` (UUID, generated by the Order Service — not by `shared-model`).
5. Remove the `jakarta.persistence-api` dependency from `shared-model/pom.xml` — confirm no remaining class in the module needs it before removing.

## Out of scope
- Do not touch `order-service` or `inventory-service` consumer/producer code in this task — that's A-4/A-5. This task only changes the contract library. (It's fine and expected that `order-service`/`inventory-service` will fail to compile against `shared-model` until A-4/A-5 land — that's the normal state between these dependent tasks.)
- Do not change `LoginRequest`/`LoginResponse`/`RegisterRequest`.

## Acceptance criteria
- `cd shared-model && ./mvnw clean install` succeeds.
- `shared-model` contains zero classes annotated `@Entity` (`grep -r "@Entity" shared-model/src` returns nothing).
- `shared-model/pom.xml` has no `jakarta.persistence-api` dependency.
- `OrderPlacedEvent`, `OrderItem`, `InventoryReservationEvent` are all records (immutable, no setters).
